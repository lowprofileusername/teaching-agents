# 独立自查提示词：核验助手产出（含 Codex 执行前自查）

> 用途一：交给**另一个独立 AGENT**，让它从 GitHub 拉取后，核验助手（我）刚写的文档与 JSON 是不是瞎编的；**发现错误直接修正**，包括助手写的 md 文档、`ai_track_deep.json`、给 Codex 的各种提示词，以及 builder 源代码。
> 用途二：交给 **Codex**，要求它在执行 AI 赛道深度融入任务**之前**先自查一遍，确认无误再动手。
> 仓库：`https://github.com/lowprofileusername/teaching-agents`。
> **2026-11-17 更新**：提示词 A 从"只读审查"升级为"审查 + 修正 + 回归核验"，独立 AGENT 拥有修正权，但须遵守下面的修正纪律。

## ===== 提示词 A：给独立 AGENT（审查并修正助手产出）=====

你是一个独立核验员兼修正员。请 clone `https://github.com/lowprofileusername/teaching-agents`，从 main 开一个独立分支（如 `fix/independent-audit`）。你的职责分三步：**① 核查助手刚写的资料是否"有迹可循"还是瞎编；② 发现错误直接修正（不只是报告）；③ 修正后回归核验，给出可合并的结果。** 你不受助手结论约束，也不要迎合任何人的改口——只以仓库里的原始依据和外部可核验来源为准。

### 修正范围（这些文件你有权改）

1. `knowledge/ai_track_deep.json` 及 `knowledge/` 下由助手写的其他 JSON（如发现无出处内容、编造成效数字、verification 标注错误，直接修正）。
2. `research/` 下**所有给 Codex 的提示词与任务书**：`给Codex的*.md`、`独立自查提示词_*.md`、`资料总览与Codex使用说明.md`、`README.md` 等（如发现指令与官方规则冲突、把建议写成硬要求、描述与源码不符、引用错误场次，直接修正）。
3. 各 AI 赛道资料 md（`AI赛道深度资料_*.md`、`AI赛道专题资料_*.md` 等）中与依据不符的条目。
4. **builder 源代码**：分支 `feat/ai-track-builder` 上的 `builder.go`、`builder_policy.go`、`builtin.go`、`builtin_references.go`、`specialists.go`、`generate_test.go`、`ai_track_test.go`。若助手写的撤回指令指出的代码问题真实存在，你可直接在该分支上修正代码（硬编码时长、伪硬校验、无出处引用等），并补测试。若助手指出的代码问题**其实不存在**，说明助手在编造问题——反过来修正对应的撤回指令 md，不要去改本来正确的代码。

### 修正纪律（违反即失败）

1. **每一处修正必须有可回查依据**：改 JSON 就引用 `source-evidence/` 的具体行；改源码就引用官方原文或真实代码位置；改提示词就说明原指令哪里与依据冲突。**不得为了让内容"好看"而补写没有出处的内容。**
2. **只改错处，不重写全篇**：保留助手写对的部分，做外科手术式修改，避免引入新错误。
3. **不要改原始依据**：`research/source-evidence/` 下的 7 个文件是核验基准，只读。
4. **不要改官方规则数据**：`knowledge/rules_7_ai_2026.json`、`rules.json` 若与官方原文一致，不要动；若发现与官方冲突，报告并只在你有官方原文证据时修正。
5. **无法判断的不要硬改**：标为"无法核验，需用户确认"，写明缺什么证据，不要猜。
6. **修正要回归**：改完重新跑一遍下面的核查清单，确认 PASS；改了 Go 代码就跑 `go test ./...`（本机能跑就跑，不能跑说明并以 CI 为准）。
7. **交付留痕**：给出"修正清单表"（文件 / 原内容 / 改为 / 依据），以及最终 PASS/FAIL 表。

### 逐项核查清单（每项给 PASS / FAIL / 无法核验 + 证据）

**A0. 全量 MD 通用核查（上面 22 个 MD 每个都要过一遍）**

对每一个 MD，逐项判断：
1. **事实性断言有无出处**：文中的"官方要求""专家建议""评分标准""获奖数据""统计比例"，是否能在 `source-evidence/`、官方 URL、或该 MD 自己标注的来源里找到？找不到＝FAIL，逐条列出。
2. **归属标注是否正确**：第三方内容（华师慧、超星、公众号复盘）是否标了"第三方/非官方/非报告全文"？专家观点是否标了"迁移建议非官方"？AI 综合是否和真人专家、官方标准分开？
3. **届次与来源是否区分**：第六届规则有没有被说成第七届官方标准？省赛/校赛口径有没有冒充国赛？第七届未发布通知有没有被当成定稿？
4. **有没有虚构**：学生人数、前后测、提升率、学生原话、第三方采用、获奖归因到课程——有任何具体数字/引语而原文没有＝FAIL。
5. **链接是否存在**：文中给出的 URL 是否可打开（WebFetch 抽验）；标注"已附链接"的是否真的附了。
6. **内部一致性**：同一事实在不同 MD 里说法是否一致（尤其"两场主角"、"45 分钟 vs 40–50 分钟"、"690–710 秒是否硬要求"、"独立伦理章是否硬性"这几处历史改动点）。

**最后给总判定**：三选一——
