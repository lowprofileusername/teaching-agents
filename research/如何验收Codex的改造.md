# 如何验收 Codex 有没有按设计改造 AGENT

> 核心原则：**不要相信"我做完了"这句话，只相信能跑出来的结果。**
> Codex 也可能偷懒——把 JSON 塞进 embed 却不写检索、加个顾问名字却没有实际逻辑、加个字段却没有生成分支。
> 这套验收分三层，从易到难，全部通过才算真的做到。

---

## 第 0 步：拿到 Codex 的改动

Codex 应该开一个独立分支（如 `feat/ai-track-builder`）并给你 PR 链接，而不是直接提交 main。
把分支拉到本地验收：

```bash
cd "D:/WorkBuddy/2026-11-16-18-31-51/_tmp/teaching-agents-repo"
git fetch origin
git checkout feat/ai-track-builder     # 换成 Codex 实际给的分支名
git pull
```

如果 Codex 直接改了 main 或没给分支，先让它补齐——这是流程要求，也是留给你的回滚余地。

---

## 第 1 层：代码层自动验收（5 分钟）

运行我写好的脚本：

```bash
cd "D:/教创赛视频"
python verify_codex_work.py
```

它会逐条打印 PASS / FAIL / RED FLAG。**当前未改造状态是 0 PASS / 4 FAIL / 8 RED FLAG**，说明脚本很灵敏：

| 检查项 | 为什么重要 | 偷懒信号 |
|---|---|---|
| 0a 独立分支 | 便于回滚、便于 review | 直接改 main |
| 1a embed 含三个 JSON | 不改 embed，新资料根本进不了程序 | 缺任一 JSON |
| 1b JSON 被实际读取/检索 | **最常见偷懒**：只塞进 embed，没有任何读取代码，程序仍读不到 | 文件名只在 embed 行出现 1 次 |
| 2a 新增 architect / video-planner | 没有这两个顾问就没有 builder | 缺任一 ID |
| 2b 前端能看到新顾问 | 顾问加了但 UI 选不到，等于没有 | 前端无注册 |
| 3a/3b generate 模式 + 生成型 prompt | 只加字段、没有生成逻辑 = 假完成 | 无新增 sys 赋值 |
| 4a/4b 测试存在且通过 | 没测试=没保障；编译都不过=直接失败 | go test 报错 |

**判定规则**：任何一个 FAIL 或 RED FLAG，把那几行原样复制给 Codex 要求修正，不要进入第 2 层。
本机若提示"未找到 go"，在有 Go 环境的机器（或让 Codex 在它那边）跑 `go test ./...`。

## 第 2 层：运行时功能验收（最关键，脚本代替不了）

代码改对 ≠ 功能真的能用。启动程序（Go + Wails 桌面端），做下面 5 个实测。

### 测试 A：内置资料能不能被检索到

在顾问对话里分别问这三个问题，看回答是否命中对应资料：

1. **问**：「第六届 AI 赛道一等奖有哪些课程和做法？」
   - ✅ 应命中 `ai_award_cases_6th.json`，说出宋晓菲《酶工程》、李静《流体力学》、辛惠娟《水力学》等，并**带来源、届次标注**
   - ❌ 答不上来 / 张冠李戴 / 不说来源 = 检索没接上

2. **问**：「第七届 AI 赛道报告评分维度有哪些？」
   - ✅ 命中 `rules_7_ai_2026.json`，列出 6 维，并显式标注"省赛校赛口径汇总，非国赛正式标准"
   - ❌ 把第六届规则当第七届官方标准说 = 届次感知没做

3. **问**：「AI 赛道怎么防止学生让 AI 代做？」
   - ✅ 命中 `ai_playbook.json` 的打法（AI 拒绝直答、审查三基准等），标注来源专家，并说明"这是迁移建议不是专家本人观点"
   - ❌ 冒充专家原话 / 冒充官方标准 = 数据纪律没做

### 测试 B：能不能"专门写"AI 赛道报告（builder 核心）

选择新顾问 `architect`（报告架构师），给它一段你的课程描述，比如：
> "我教《数据结构》，大二学生，想参加第七届 AI 赛道，帮我搭报告骨架。"

- ✅ 应输出：**分章节骨架 + 每节字数预算 + 每节必答问题 + 需你补充的证据清单 + 6 维评分对照表 + 伦理治理内容落点（可置于课程思政章节，独立成章不强制，见撤回指令）+ 一句话创新主线**
- ✅ 6 维对照表的维度名称应与 `rules_7_ai_2026.json` 完全一致（问题导向/创新特色/课程思政/创新构建教学环境/技术应用于教学/成果辐射），证明它真读了规则而非写死
- ✅ 引用往届案例时会标注"这是往届做法，不是你的课程事实"
- ✅ **赛道切换测试**：把赛道改成"新文科"再让它搭骨架——应输出新文科的 5 维对照表、**不应**再出现"AI 伦理治理章节"。若换赛道仍冒出 AI 专属内容 = 维度写死了，不合格
- ❌ **致命失败**：它替你编造"学生满意度提升 32%""覆盖 500 人""获省级奖项"——只要出现你没提供的具体数字/成果，就是设计被破坏，立即打回
- ❌ 只输出一堆泛泛建议、没有字数预算和证据清单 = 不是设计中的 architect

### 测试 C：能不能"专门检查"报告

选 `report` / `ai` / `evidence` 顾问，贴一段你自己的报告草稿，要求按 AI 赛道 6 维检查。

- ✅ 应能指出"AI 介入环节人机分工不清""成效缺改革前后可追溯数据""伦理治理内容缺落点"等**赛道专属问题**
- ✅ 沿用原有 checker 输出纪律（StructuredReview 的 JSON 格式），不破坏旧能力
- ❌ 只用通用话术检查、看不出 AI 赛道特点 = 新资料没进入审阅 prompt

### 测试 D：AI 赛道完整视频策划（两项视频，不是一个 45 分钟）

选 `video-planner`，要求为你的 AI 赛道课程规划参赛视频。**AI 赛道要交两项视频，时长和形式不同**，必须两项都规划到：

- ✅ **视频①课堂实录**：40–50 分钟关键教学行为时刻表（时间段 / 教学环节 / AI 介入动作 / 要拍到的学生行为证据 / 对应报告举措），并体现连续录制、主讲出镜、有学生镜头、机位≤2、不配音/画中画等约束
- ✅ **视频②课外教学展示**：≤15 分钟**说课形式**，覆盖课前、课后的 AI 融入全过程（课中衔接段可选，非官方硬要求），输出分段脚本（课前 AI 做什么 / 如需可加课中衔接 / 课后 AI 如何延伸 / 每段要展示的 AI 界面或学生产物证据）
- ✅ 两段共同约束：都体现 AI 应用、教案课件标注四项（应用环节/设计目的/操作流程/预期效果）、命名规范、两段围绕同一创新主线呼应
- ✅ 引用"AI 只追问不代答""AI 幻觉逆向训练"等打法，并标注来源专家与"迁移建议"性质
- ❌ 只规划了 45 分钟课堂、**漏掉 15 分钟说课视频** = 不合格（这是常见缺陷）
- ❌ 只有环节名称、没有可拍摄的学生行为证据 = 不合格

### 测试 E：回归——旧功能没被改坏

- 原有 8 个顾问仍都在、都能用
- 原来的"文字审阅 / 图文审阅 / 结构审阅"三个结构化输出仍是原来的 JSON 格式，没有多加字段或 Markdown 围栏
- 7 个工作区能正常打开

## 第 3 层：数据纪律抽检（贯穿上面所有测试）

这是整个工作台的灵魂，任何一条违反都要打回：

1. **三者分开**：AI 建议 ≠ 真人专家观点 ≠ 官方评分标准，回答里必须能看出区别
2. **届次标注**：第六届规则只能作往届参考，第七届资料标注"非正式标准"
3. **不虚构**：不编造学生人数、前后测、提升率、学生原话、第三方采用
4. **来源归属**：获奖案例是公开报道不是报告全文；第三方转载内容保留归属标记
5. **不冒充**：不声称"已阅读你上传的材料"，除非你本轮真的提供了
