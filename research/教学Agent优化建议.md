# teaching-agents 工作台优化建议：用于第七届 AI 赛道报告 + 45 分钟视频备赛

> 基于对 github.com/lowprofileusername/teaching-agents v0.4.1 源码的审阅（2026-11-16）
> 结合第七届 AI 赛道官方评分表 + 36 场国赛专家方法论 + 你本地的证据底座

---

## 一、先给这个工作台一个准确判断

**它现在的强项 = 审阅/核查（checker）**：8 个 AI 顾问全是"检查型"（chief/report/lesson/presentation/evidence/ai/values/rules），核心 prompt 是"逐段审阅→给 comment + replacement"。加上只读专家库（36 场视频/页面/转写）、六项证据链、数字提及清单、课堂字幕时间轴检查——这套"防止你写错、写虚、前后矛盾"的能力非常扎实，正好命中评委最反感的"技术堆砌、无证据、逻辑不闭合"。

**它现在的短板 = 从零构建（builder）**：你现在的核心任务是"从零写 4000 字报告 + 规划 45 分钟视频内容"，而工作台没有"生成骨架/生成脚本/生成拍摄清单"的能力。它只能等你上传初稿后逐段挑错。

**结论：不要推倒重来。** 在现有架构上补 3 个"builder 能力 + 1 个数据接入"即可，你的 checker 体系会成为质量把关的护城河。

---

## 二、缺口 1：缺"报告架构师"生成器（最高优先级）

### 现状
 specialties.go 的 8 个顾问全是检查清单（Checks），没有一个是"给你一份可直接填的 4000 字骨架"。报告工作区只接受已上传 DOCX 再逐段审阅。

### 建议：新增第 9 个顾问 `architect`（报告架构师）
在 `specialists.go` 的 `teachingSpecialists` 数组加一条，并在 `trackFocus` 用 AI 赛道专属焦点：

```go
{"architect", "报告架构师", "从零生成4000字报告骨架与逐段字数预算",
 []string{"课程痛点是否可溯源到学情数据", "能否提炼唯一创新主线并配逻辑图", "6维评分每项在报告中的落点是否可见", "成效是否有改革前后可追溯数据", "AI伦理治理是否单列"},
 "分章节骨架、每节字数预算、每节必答问题、需补充的证据清单",
 "生成报告 大纲 骨架 从零写"},
```

### 配套：加一个"生成模式"API
现在 `main.go:193` 的 system prompt 是"文字审阅顾问"（只输出 comment/replacement JSON）。建议在 main.go 增加一条 `sys`（生成模式），让它输出结构化大纲 JSON：

```
你是教学创新报告架构师。根据我提供的课程信息、赛道、学情痛点、AI应用场景，
生成一份4000字报告骨架：每章标题、字数预算、该章必答的2-3个问题、
需要我提供的数据/截图清单。只输出JSON，不编造任何我的课程事实。
```

**关键**：让它输出"待补证据清单"（你要提供什么），而不是替你编数据——这与工作台"不虚构成果"的现有纪律一致。

### AI 赛道专属：让架构师强制产出这 4 项
1. 一句话创新主线（如"人机协同·判断力生成"）
2. 逻辑闭环图描述（痛点→理念→举措→成效→推广）
3. 独立的"AI 伦理与治理"章节（对应官方第 3 维，多数人漏）
4. 6 维评分对照表（每维标注写在哪一节）

## 三、缺口 2：缺"45 分钟视频"的脚本/拍摄规划生成器

### 现状
课堂实录工作区只做字幕（SRT/VTT）时间轴检查、行为手动标注、选段审阅——都是"录完之后"的事。README 明确写"未集成原视频自动听辨"。而且官方 AI 赛道视频要求是**1 学时 40–50 分钟连续实录 + ≤15 分钟课外说课**，45 分钟属于正常区间。你没有现成字幕时，这个工作区帮不上忙。

### 建议：新增第 10 个顾问 `video-planner`（视频策划），并给它一个专用工作区

**核心功能：把报告的 2–3 个创新点映射成 45 分钟课堂的"关键教学行为时刻表"**

生成物应包含：
| 时间段 | 教学环节 | AI 介入动作 | 学生行为证据（要拍到的） | 对应报告举措 |
|---|---|---|---|---|
| 0–5' | 导入/前测 | AI 生成图当场挑错（专家方法4.4） | 学生指出幻觉的发言特写 | 举措1 |
| 5–15' | ... | AI 拒绝直答三连问（方法4.1） | 学生被追问后的思考/讨论 | 举措1 |
| 15–30' | ... | AI 方案盲评（方法4.2） | 投票、坚持正确判断的画面 | 举措2 |
| ... | | | | |

**为什么这正好补你的短板**：官方课堂实录评分看"教学理念/内容/过程/效果/视频质量"，且明确要求"体现 AI 应用"。你本地专家库的打法（AI 拒绝直答、盲评、审查三基准）都可以变成"要拍到的关键行为"——先设计拍什么，再录，素材就一定是评委想看的。

### 复用现有能力
`lesson` 顾问（课堂实录顾问）的 Checks 已经是"教师提问—学生思考—反馈的互动链""视频选段与报告主张一致""区分可观察行为与仅字幕无法证明的行为"——把 `video-planner` 生成的时间表喂给 `lesson` 顾问审阅，正好形成"先规划→后录→再核查"的闭环。

## 四、缺口 3：内置规则库是第六届，需加第七届 AI 赛道层

### 现状
`knowledge/rules.json` 顶部已诚实标注：`edition:6`、`status:"第六届国赛正式文件；用于第七届及以后备赛时仅作往届参考"`。AI 赛道 6 维评分（问题导向/创新特色/课程思政/创新构建教学环境/技术应用于教学/成果辐射）是对的。

### 建议：新增 `rules_7_ai.json`（或给 rules.json 加一个 edition 7 的 group）
把今天全网核实到的第七届信息写进去（国赛正式通知未发布，标注为"省赛/校赛口径，待国赛确认"）：
- 技术门槛：智慧教育平台资源 or 自建教学智能体（二选一）
- 至少 2 个 AI 情境（6 选 2）
- 视频：40–50 分钟连续实录 + ≤15 分钟课外说课
- 报告：≤4000 字、≤95MB、查重<20%、匿名
- 分组：部属高校组 / 地方高校组（不按职称）
- 第七届新增"原创性教材应用赛道"（待国赛确认）

让 `rules` 顾问（当前 checks 已包含"来源属于当届国赛、校赛还是往届参考"）在答第七届问题时能检索到这一层，避免它只会说"这是第六届参考"。

## 五、缺口 4：把你的证据底座接进工作台（这是你独有的）

你本地有一套 36 场专家视频分析（skill 的 references），而工作台的只读 SQLite 专家库（expert_videos_v1/v2）就是同一批素材。两者可以打通：

1. **用 `library_query.py` 做桥接**：README 示例 `python library_query.py --db expert_videos.db page song:P12`。你可以把 skill 里的 `04_AI教学创新迁移清单.md`（9 类打法）和 `01_评委判据与赛制.md`（评委三档、往届数据）转成可检索条目，纳入工作台的专家库检索。
2. **给 4 个 AI 打法打标签**：AI 拒绝直答（张静）、AI 方案盲评（辛页）、审查三基准（于歆杰）、AI 治理边界（辛页）——在 `video-planner` 和 `architect` 的 prompt 里作为"可选教学机制库"引用，让生成器能主动建议使用。
3. **保持"AI 建议 ≠ 专家本人观点"的纪律**：工作台现有 prompt 已经很严格地做了这点（experts.go:115），沿用它，让建议标注"基于张静某场比赛的做法迁移"，不冒充真人。

## 六、推荐的工作流（把工作台用出最大价值）

```
第1步  architect（新）    → 生成 4000 字骨架 + 证据清单 + 6 维对照表
第2步  你               → 按证据清单采集真实数据/截图（AI 后台日志、前后测）
第3步  你               → 填入骨架，形成初稿 DOCX
第4步  report 顾问       → 逐段审阅（现有能力）：逻辑闭合、痛点对应、删废话
第5步  evidence 顾问     → 核查数据口径：样本/分母/基线/量规/因果（现有能力）
第6步  ai 顾问           → 检查 AI 必要性、人机分工、伦理防代做（现有能力）
第7步  video-planner（新）→ 生成 45 分钟关键行为时刻表 + 15 分钟说课要点
第8步  你               → 按时间表录课
第9步  lesson 顾问       → 上传 SRT 字幕，核查互动链与报告一致（现有能力）
第10步 presentation 顾问 → 12 分钟汇报逐页审阅 + 评委追问（现有能力）
```

**关键：第 2 步不能省。** 工作台再强也不会替你产生真实教学数据；AI 赛道最看重的就是"真实使用痕迹"，临时搭建会被质疑。

## 八、一句话总结

你的工作台已经把"写错、写虚、前后矛盾"这条路堵得很死了；现在缺的是"从零起稿"和"拍摄前规划"这两个 builder。补上 `architect` 和 `video-planner` 两个顾问 + 第七届规则层，再用 `library_query.py` 把你本地 36 场专家方法论接进去，就能形成"生成→填证据→8 顾问审阅→视频规划→录后核查"的完整闭环。这套组合拳在 AI 赛道尤其有效，因为它同时满足了官方最看重的两件事：**系统性设计** 和 **基于证据的成效**。
