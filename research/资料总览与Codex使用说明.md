# 资料总览与 Codex 使用说明

> 本文件是仓库研究资料的**总入口**。Codex / 开发者请先读这份，再决定改哪里。
> 整理时间：2026-11-16。所有资料由 AI 助手联网检索 + 用户本地 36 场专家视频库整理，非官方标准。

---

## 0. 一句话任务

用户（一位教师）正在备战**第七届全国高校教师教学创新大赛 · 人工智能赛道**，用本仓库 `teaching-agents` 工作台辅助写 4000 字创新成果报告、规划 45 分钟课堂实录。
当前工作台**强在 checker（审阅核查），弱在 builder（从零生成）**。资料的目标是把"AI 赛道怎么写、怎么查"变成 agent 真正能调用的能力。

## 3. Codex 实施顺序（照这个做）

1. **先读** `research/给Codex的提示词.md`，严格按四步实施（内置资料 → 2 个 builder 顾问 → generate 模式 → 回归测试 + 分支 PR）。
2. **内置三个新 JSON**：改 `builtin.go` 的 `//go:embed`，并参照 `builtinLibrary()` 的只读加载 + `builtinRuleSearch()` 的检索方式接入。注意四个 JSON 的届次/性质不同，回答要能区分：
   - 第六届规则 = 往届参考
   - 第七届规则 = 非正式标准
   - 打法库 = AI 迁移建议，非专家本人观点、非官方评分
   - 获奖案例 = 公开报道，非报告全文、非用户成效
3. **新增顾问**：`architect`（报告架构师）、`video-planner`（视频策划），更新 `specialists.go` 的 `teachingSpecialists` 与前端顾问选择。
4. **生成模式**：`main.go` 加 generate 分支，输出结构化骨架 + 字数预算 + 待补证据清单；**绝不替用户编造学生数据/成效**。
5. **自测**：对照 `research/如何验收Codex的改造.md`，运行 `verify_codex_work.py`（脚本在用户本地，可让用户跑），确保没有"只塞 embed 不写检索""只加字段没加逻辑"的假完成。
6. **交付**：独立分支 + PR，列出改动文件、顾问 ID、embed 与检索路径、测试命令与结果。

---

## 4. 必须守住的数据纪律（违反即打回）

1. **三者分开**：AI 建议 ≠ 真人专家观点 ≠ 官方评分标准。
2. **届次标注**：第六届只能作往届参考；第七届资料标注"非正式标准"。
3. **不虚构**：不编造学生人数、前后测、提升率、学生原话、第三方采用。
4. **不冒充**：不声称已阅读用户材料或已观看视频，除非本轮确实提供。
5. **案例边界**：获奖案例只能证明"某做法有先例"，不能证明用户课程已有效。
